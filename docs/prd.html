Alur

A simple personal CRM for managing contacts and the deals attached to them. You keep a pipeline of deals with a value in Indonesian Rupiah (IDR) and a status, move them on a Kanban board, see a timestamped activity history on each deal, and never lose the next follow-up — both on the deal itself and as a single to-do list across everything you're working. The app is Phoenix + LiveView with SQLite; from milestone 7 the Pipeline path moves to Vue over a REST API. Build it in eight browser-testable milestones.

Phoenix LiveView SQLite Vue Vite REST Nix flake (Elixir 1.20 / OTP 27)

What the app does

  • Login and layout

    Register with email and password, log in and out. After login: nav to Pipeline, Contacts, and To-dos. Pipeline is home.

  • Contacts

    List, search by name, add/edit/delete. Name required; email, phone, company, notes optional. Open a contact to see deals and start a new one.

  • Deals

    Each deal has a title, IDR value (shown as e.g. Rp 15.000.000), a contact, a pipeline column, and optional notes. Open, edit, or delete from the deal page.

  • Kanban pipeline

    Five columns: Lead, Meeting, Proposal, Won, Lost. Cards show title, contact, IDR. Drag to change status. Column totals. Click a card to open the deal.

  • Deal activity log

    Newest-first history on the deal: created, moved, follow-up added or completed, plus manual notes you type. Lines are not edited later.

  • Next actions

    Schedule a follow-up on a deal (description + due date, optional time). Incomplete items appear on a global To-do list, soonest first, overdue called out. Mark done from the deal or the list.

Already provided by the existing codebase

  • Nix dev shell (Elixir 1.20, OTP 27, SQLite, Node)
  • Credo / editorconfig / Reach config

No Phoenix app, pages, or login exist yet. Milestone 1 creates the app. Login, layout, and every CRM feature are in v1 — nothing of the product is pre-built.

Out of scope (v1)

  • Teams, roles, and sharing — this is your pipeline, not a company-wide CRM. Extra accounts do not share data.
  • Email and calendar sync — no Gmail, Outlook, or Google Calendar. Reminders live in the app.
  • Native mobile app — phone browser is enough.
  • Import/export — no HubSpot, Salesforce, or CSV. You add contacts yourself.
  • Invoices, quotes, payments — deals have an IDR value; money does not move through the app.
  • Multiple pipelines, currencies, custom fields — one IDR pipeline, fixed fields and columns.
  • Reports and forecasts — Kanban, activity, and to-dos are the views. No charts or win-rate dashboards.
  • Automation and email sequences — next actions are something you schedule, not a drip campaign.
  • Google/GitHub login, magic links, 2FA, email password reset — email/password only. No mail provider in v1.

Milestones

1

Login and shell

Stand up the Phoenix app and the signed-in chrome. You can register, log in, and move between empty placeholder pages.

What gets built

  • Phoenix + LiveView app using SQLite, runnable from the existing Nix shell
  • Register with email and password; log in and log out
  • Logged-out visitors only see sign-in / register
  • After login: nav — Pipeline, Contacts, To-dos — plus log out. Pipeline is home
  • Pipeline and To-dos may be empty placeholders

Not in this milestone

  • Contacts, deals, Kanban, activity, or next actions
  • OAuth, magic links, 2FA, or email password reset

Done when: In the browser you can create an account, log in, see the nav, open the three sections, and log out. A logged-out visit cannot see the app.

2

Contacts

You can keep a real contact list and open each person.

What gets built

  • Contacts page listing name, company, and email
  • Search/filter the list by name
  • Add, edit, and delete (name required; email, phone, company, notes optional)
  • Contact detail page with those fields
  • You only see your own contacts

Not in this milestone

  • Deals on the contact, or a “new deal” button that works
  • Import, tags, bulk edit, photos, companies as their own records

Done when: Logged in, you can add a contact, find them by name, edit, open their page, and delete them. Another account does not see that contact.

3

Deals

Deals exist with an IDR value and a contact. You manage them from the contact and a deal page — not yet from a board.

What gets built

  • Create a deal from a contact: title, IDR amount, starting column, optional notes. Contact is required
  • IDR shown as rupiah everywhere (e.g. Rp 15.000.000)
  • Deal page: title, value, contact, column, notes
  • Edit those fields; delete the deal
  • Contact detail lists that contact’s deals
  • Five columns exist as data (Lead → Lost) even if the Kanban UI is not built yet; new deals pick a starting column

Not in this milestone

  • Kanban drag-and-drop or column totals
  • Activity log or next actions on the deal page
  • Multiple currencies, line items, quotes

Done when: From a contact you create a deal with an IDR value, open it, see rupiah formatting, change the column on the deal page, and delete it. The contact shows the deal in its list.

4

Kanban pipeline

The Pipeline page becomes the working board. Dragging a card is how you change status.

What gets built

  • Pipeline page: columns Lead, Meeting, Proposal, Won, Lost in that order
  • Each card: deal title, contact name, IDR value
  • Drag a card to another column; that is the deal’s new status
  • Click a card to open the deal
  • IDR total per column

Not in this milestone

  • Adding, renaming, reordering, or deleting columns
  • Filters, swimlanes, WIP limits, card colors
  • Activity log entries for a move (that is milestone 5)

Done when: Existing deals appear on the board in the right columns. You can drag one from Lead to Meeting, refresh, and it stays there. Column totals match the cards. Clicking a card opens the deal.

5

Activity log

Each deal keeps a timestamped history of what happened, plus notes you write yourself.

What gets built

  • On the deal page, a log newest-first with date/time and a short description
  • A line when the deal is created and when it moves column (including Kanban drags)
  • You can add a free-text note to the log
  • Hook points ready for next-action add/complete lines in milestone 6

Not in this milestone

  • Editing or deleting log lines
  • A global activity feed across all deals
  • Attachments, call recording, comment threads
  • Follow-up add/complete events (milestone 6)

Done when: Opening a deal shows a created line. Dragging it on the board (or changing column on the deal page) adds a move line with a timestamp. You can type a note and see it in the log. You cannot edit or delete a line.

6

Next actions

Follow-ups live on the deal and on one To-do page for everything still open.

What gets built

  • On a deal: add a follow-up with description and due date (optional time)
  • Incomplete actions are obvious on the deal; completed ones stay visible on the deal
  • Mark done from the deal page
  • To-do page: all incomplete actions across deals, soonest due first; row shows what, when, and which deal; click through to the deal
  • Mark done from the To-do page
  • Overdue items are visually distinct
  • Adding or completing a follow-up writes an activity log line on the deal

Not in this milestone

  • Email, push, SMS, or calendar reminders
  • Recurring tasks, subtasks, assignees, extra priority fields, a calendar view

Done when: You add a follow-up on a deal, see it on the To-do page with the deal name, see an overdue item called out if the due date is in the past, mark it done from either place, and see matching lines in the deal’s activity log.

7

API health and Vue scaffold

Stand up the JSON API surface and the Vue frontend toolchain so later milestones can rewrite the Pipeline board without inventing plumbing.

What gets built

  • GET /api/health — unauthenticated, returns {"status":"ok"}
  • Vue 3 + TypeScript + Vite + Vitest inside Phoenix assets/
  • Phoenix serves a Vue mount page (stub is enough: Vue boots and can show health ok)

Not in this milestone

  • Kanban REST endpoints or drag-and-drop
  • Replacing the LiveView Pipeline board
  • Extra /api resources beyond health

Done when: An unauthenticated GET /api/health returns {"status":"ok"}. A signed-in user can open a page that is a Vue app. mix test and Vitest both pass.

8

Vue Kanban over REST

Replace the LiveView Pipeline board with a Vue board that loads and updates deals through the JSON API. Same UX as milestone 4; contacts, deal pages, activity, and to-dos stay LiveView.

What gets built

  • JSON endpoints to list deals on the board and update a deal’s column on drag
  • Vue board on the same Pipeline nav/home route: five columns, card title/contact/IDR, column totals, click-through to the existing LiveView deal page
  • Drag to another column persists; refresh keeps the new column; activity-log move lines from milestone 5 still fire

Not in this milestone

  • Rewriting contacts, deal pages, activity, or to-dos to Vue
  • JWT or token auth; CORS; a separate frontend app
  • Adding, renaming, reordering, or deleting columns

Done when: Existing deals appear on the Vue board in the right columns. You can drag one from Lead to Meeting, refresh, and it stays there. Column totals match the cards. Clicking a card opens the LiveView deal page. The board talks to /api, not LiveView events.
